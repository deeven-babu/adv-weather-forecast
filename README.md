# AI-Based Smart Weather Forecast and Multi-Hazard Disaster Alert System

Phase 5 adds an AI rainfall estimate to the live dashboard. Users can search for a city, view current conditions and a seven-day forecast, explore the interactive map, and see a rainfall probability generated by a persisted Random Forest model. Flood prediction, heatwave prediction, and alerts remain outside this phase.

## Installation

1. Create and activate a virtual environment:

   ```powershell
   py -3 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

2. Install dependencies:

   ```powershell
   python -m pip install -r requirements.txt
   ```

3. Copy `.env.example` to `.env` and replace the development secret. To use MySQL, set `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD`, or provide a complete `DATABASE_URL` such as `mysql+pymysql://user:password@localhost/weather_ai`.

On startup, SQLAlchemy's `db.create_all()` creates the seven Phase 2 tables: users, locations, weather records, predictions, risk assessments, alerts, and notification preferences. SQLite is used automatically when no database environment variables are present, which keeps local development straightforward.

## Weather API

Phase 3 uses the free Open-Meteo services, so no weather API key is required:

- `https://geocoding-api.open-meteo.com/v1/search` converts a city or town name into coordinates.
- `https://api.open-meteo.com/v1/forecast` returns current conditions and seven daily forecast records.

The reusable implementation is in `services/weather_service.py`. The protected dashboard at `/dashboard?city=Chennai` uses it for HTML, and `/api/weather?city=Chennai` returns the same processed data as JSON. Search failures, empty input, timeouts, unavailable services, and incomplete responses are converted into friendly messages. External requests are mocked in `tests/test_weather.py`, so the test suite does not depend on the live service.

## AI Rainfall Prediction

The training data is the WeatherAUS dataset, originally collected from the Australian Bureau of Meteorology and distributed through public WeatherAUS dataset mirrors. The CSV uses historical observations and the `RainTomorrow` target (`Yes` = rain, `No` = no rain). The six model features are temperature, humidity, pressure, wind speed, precipitation, and cloud cover.

`ml/preprocessing.py` removes duplicate source rows, converts numeric fields, drops invalid target labels, and leaves missing feature values for median imputation inside each model pipeline. `ml/train.py` creates a stratified 80/20 split, compares Random Forest, Logistic Regression, and Decision Tree models, runs three-fold F1 cross-validation, writes accuracy/precision/recall/F1/confusion matrices to `ml/models/evaluation.json`, and saves the best model to `ml/models/rainfall_model.joblib`.

To retrain from a legitimate CSV with the same columns:

```powershell
.\.venv\Scripts\python.exe -m ml.train --dataset ml/data/weatherAUS.csv
```

The Flask dashboard loads the saved artifact through `ml/predict.py`; it never trains when the application starts. Current Open-Meteo values are converted to model features, and unavailable optional values such as cloud cover are handled by the trained imputer. The result is labeled as an AI estimate, not an official forecast.

Run the Phase 5 tests with:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_ml.py -q
```

## Run

```powershell
flask --app app run --debug
```

Open `http://127.0.0.1:5000/` for the home page. The health endpoint is available at `http://127.0.0.1:5000/health` and returns `{"status":"ok"}`.
